## 1. 专家团对初案的真实评估

### 1.1 分席摘要

| 席位 | 对初案 | 要点 |
|------|--------|------|
| **定价** | 方向对，未完成 | 「一周内免费一次」解决伦理与获客；但 **standard/compressed 若仍是月费绑剩余周**，A=30/B=50 单位不公仍在。底线要求 **付费段也必须有同一时间单价**。 |
| **产品 / Freemium** | 赞成 sprint 一生一次 | 与「短档信任不足不宜旅程型强收」一致；防刷比「sprint 永久免费」干净。须定义第二次付的是什么。 |
| **UX / 心理** | 赞成不趁火打劫 | 紧急免费 = 尊严与信任；第二次付费须像「继续用同一价的服务」，不像惩罚税。悬崖在 D=6 vs D=7 要诚实说清。 |
| **行为 / 滥用** | 有条件赞成 | 一生一次挡「无限刷 sprint」。剩：多账号、把考期改成 6 天骗首次免费——MVP 可接受；靠账号权益戳 + 不重置。 |
| **伦理 / 品牌** | 强赞成 | 临考不涨价、不恐吓，符合底线。 |
| **学习科学** | 赞成免费紧急窗 | 紧急交付应是窄突击清单，不是全课——避免「一次免费 = 整份 HSK」。 |
| **增长** | 赞成 | 一次免费紧急 = 高质量获客钩；转化放在「还要再来 / 要走长程」时。 |
| **单人创始人** | 赞成简化版 | 先锁 **时间单价 R** + **免费紧急一次**；SKU 尽量少（考期包或「按周余额」一种主路径即可）。 |
| **信息架构** | 中性 | 三档仍是时长呈现；**计费状态**另轴（免费本程次数 / 已购周数），不要为计费新开 App。 |
| **售后** | 提醒 | 考期包/按周：改考期、退款规则要写死；紧急免费不承诺过线。 |

### 1.2 对初案的三句话判决

1. **「≤7 天一生一次免费」——采纳**（伦理、信任、防刷三者同时成立）。  
2. **「standard/compressed 可收费」——采纳，但必须补上单位时间定价**；否则你今早的 A/B 不公仍在，底线未落地。  
3. **「再使用须付费」——采纳**；第二次起按 **同一时间单价** 买天数/周，**禁止**紧急溢价。

## 2. 终案原则（联合签字）

### P1 · 计量单位（可量化）

> **价值单位 = Coach-day（教练日）**  
> 展示层可换算为周：`1 Coach-week = 7 Coach-days`。  
> 全产品只有一个标价率 **R = 价格 / Coach-day**（或等价的「每周 W = 7R」对外更好读）。

- 不问「这个月解锁了多少剩余周是否吃亏」。  
- 问「我为多少个教练日付钱，单价是否与别人相同」。

### P2 · 不趁火打劫

> 同一账号、同一单价 R。  
> **禁止**因 D 变小而提高 R（无紧急溢价、无「明天考加价」）。

### P3 · 信任先行（付费段）

> standard / compressed：**第一可执行周（本程）Free 给满**（保留现有信任仪式）。  
> 付费只覆盖 **本程之后的剩余 Coach-days**（或用户购买的权益窗）。

### P4 · 紧急善意（sprint）

> `exam_sprint`（建议阈值：**1 ≤ D ≤ 6**，今天考并入）：  
> **每账号 lifetime 一次**完整紧急方案 Free（诊断 + 报告 + 单窗突击给满）。  
> 再次进入 sprint（或等价短窗）：按 **D × R** 付费（与长档同一 R）。

### P5 · 货与价对齐

> 用户买到的是 **可执行教练时间**（任务/周解锁），不是「模糊的月费运气」。  
> 工具型权益（模考额度、写作评分等）打成 **付费席附带包**（Paid seat），随付费席生效，避免第二套难懂货币。

## 3. 主计费形态（推荐落地）

**推荐主路径：考期余额包（Runway pack）——按 Coach-day 计价，一次买清「本场剩余付费日」。**

可选并行（二期）：日历月订阅 = 预充 `≈30 Coach-days` 余额，同一 R，用完再买/再订——避免「同学费不同旅程」的错觉。

**首版只做 Runway pack + 紧急一次免费即可**（单人可运维）。

### 标价展示（心理）

| 对内 | 对外文案方向 |
|------|----------------|
| R / day | “About $W per week of your plan” |
| Pack = ceil(paid_days) × R | “Cover the rest of this exam runway” |
| Sprint 2nd = D × R | “Another emergency plan — same daily rate, no rush fee” |

## 4. 三档如何适配

| `plan_mode` | 距考（建议） | Free 给什么 | 何时付费 | 付多少（公平） |
|-------------|--------------|-------------|----------|----------------|
| **standard** | D≥21 或 unsure | 诊断+报告+大纲可见+**Week 1 执行** | W1 清关后主转化 | 剩余旅程 Coach-days × R（Runway pack） |
| **compressed** | 7≤D≤20 | 同上（第一可执行周） | 第一周清关后 | 剩余压缩 Coach-days × R |
| **exam_sprint** | 1≤D≤6（含 D=0） | **Lifetime 首次：** 整段紧急方案给满 | 不在首次清关逼旅途续费 | **第二次及以后：** D × R；无溢价 |

### 边界与悬崖（诚实）

| 场景 | 规则 |
|------|------|
| D=6 首次 | Free sprint（戳 `free_sprint_used_at`） |
| D=6 再次（同账号） | 付费 D×R 后生成 |
| D=7 | compressed：Free 第 1 周；若总跨度≈1 周，清关后剩余付费日可为 0（整场等价 Free）——**允许**，与「短则多免」一致，不视为漏洞 |
| 改短考期骗免费 | 仅当 `free_sprint_used_at` 为空且 mode=sprint 才免；**用过不再免** |
| Custom replan | 不重置 `free_sprint_used_at`；不白送新的付费余额 |
| 中途升级 | 允许；按剩余付费日补差或购 pack，不重走 setup |

### 与「砍 sprint」意向的关系

昨日曾倾向砍 sprint。本终案 **保留 sprint 作为免费紧急窗（一次）**，因为：

- 满足「一天也不趁火打劫」；  
- 比「禁止选 &lt;7 天」更人道；  
- 一生一次已回答防刷。

若你仍坚持砍 sprint：改为「&lt;7 天禁选/只引导改期」，则 P4 删除，但 **单位时间单价 + 长档余额包** 仍应保留（否则 A/B 不公未解）。

## 5. 用户心理与体验（设计约束）

| 时刻 | 应感到 | 禁止感到 |
|------|--------|----------|
| 首次临考 sprint | 「雪中送炭」 | 「顺便推销月费」 |
| W1/本程清关（standard/compressed） | 「下一段按周计价，算得清」 | 「怎么和别人同月费我剩的少」 |
| 第二次短窗 | 「同一单价再买几天」 | 「惩罚税 / 趁我急宰我」 |
| 拒付费 | 大纲可见、本程成果保留 | 死胡同、羞辱 |

主转化文案方向（standard/compressed）：

> “Week 1 was free to prove the Coach. Cover the remaining N days of this runway — same rate for everyone.”

紧急第二次：

> “You’ve used your one free emergency plan. Another N-day plan is N × daily rate — no rush surcharge.”

## 6. 滥用与风险（诚实）

| 风险 | 等级 | 处置 |
|------|------|------|
| 多账号骗多次免费 sprint | 中 | MVP 接受；日后设备/支付指纹可选 |
| D=7 整场几乎 Free | 低 | 接受（善意）；内容仍是一周量，不是全 HSK |
| 报告不尖导致免费 sprint 无口碑 | 高 | 工程优先保证短档报告质量 |
| 考期包退款/改期 | 中 | 规则：改期按未使用 Coach-days 折算或 Custom 换约；首版可「购后 7 日未开第二周可退」 |
| 与旧「月费 Pro」SKU 并存混乱 | 中 | 首版叙事切换为 Runway pack；旧月费可映射为 30 Coach-day 预充 |

## 7. 对现有方案的修订条款（正式）

### R-Pay-1 · 价值单位

引入产品级 **Coach-day** 与标价率 **R**；对外以周表述。废止「月费同学费 = 公平」作为主叙事。

### R-Pay-2 · standard / compressed

保留 Free **第一可执行周**；清关后主转化改为购买 **剩余 Coach-days 的 Runway pack**（单价 R），不再默认「月费解锁神秘数量的剩余周」。

### R-Pay-3 · exam_sprint

保留三档中的 sprint（1–6 天）。**每账号 lifetime 一次 Free 紧急方案。** 字段建议：`free_sprint_used_at`。再次 sprint：D×R，无紧急溢价。

### R-Pay-4 · 工具权益

模考额度、写作评分等：归入 **付费席（持有未过期 Runway / 预充余额）** 附带，避免第二货币。

### R-Pay-5 · Custom replan

不重置免费紧急戳；消耗或保留余额规则在实施计划写死（推荐：未用完 Coach-days 可转到新考期窗口）。

### R-Pay-6 · 不变量仍有效

诊断中途、本程执行中途不炸主墙；不恐吓；Auth 不覆盖已购席。

## 8. 调整后端到端叙事（闭环）

```
注册 → 考期
  → standard / compressed / sprint（按 D）
  → 诊断 → 报告
  → ┬─ standard/compressed：生成旅程；Free 执行第 1 周
     │     → 清关 → 购 Runway pack（剩余天 × R）→ 续周执行
     └─ sprint 首次：Free 紧急方案给满 → 结束本场；弱转化或不转化
           sprint 再次：购 D×R → 生成紧急方案
  → Custom：整单替换；免费紧急不刷新
  → Dashboard 为家；Sign out / in 按 DB
```

## 9. 专家团最终推荐（一句话）

> **全场同一 Coach-day 单价；长档用「免费第一周 + 剩余天数包」收公平的钱；短档用「一生一次免费紧急方案」表达不趁火打劫，第二次起仍按同一单价买天数——接受你的初案骨架，并补上单位时间定价，否则底线落空。**
